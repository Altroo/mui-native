# Native positioning engine

This engine ports the positioning and modifier algorithms used by Material UI 9.5.0's Popper and connects them to measured native frames. The public [native Popper component](popper.md) supplies original imports, React composition and lifecycle. Autocomplete remains unfinished.

The engine accepts native measurement snapshots through a platform adapter. It does not create DOM objects or a WebView, import the browser Popper runtime, request editor focus, or add a modal window. Its implementation lives under `packages/material/src/nativePopper`; these are internal modules, not supported package entry points.

## Implemented engine contracts

- All fifteen placement names, original auto/fallback ordering, offset callbacks, flip variations, overflow prevention and tether calculations, optional native arrow geometry, hide metadata and native positioning styles.
- Modifier merging by name, dependency and phase ordering, per-cycle data and resets, custom modifier functions/effects, `setOptions`, synchronous `forceUpdate` when native bounds are synchronous, batched promise-based `update` and idempotent `destroy`.
- Native adapters may return asynchronous measurements. Generation guards reject stale reads after newer updates, option changes, disconnection or destruction. Asynchronous errors are reported by the adapter; invalid native measurements, non-finite positioning and unbounded modifier resets fail explicitly.
- Cleanup attempts every registered effect, releases returned effects during reentrant destruction and prevents effect registration after destruction. These are explicit native lifecycle safeguards.

`viewport` and `document` are separate bounds. A missing clipping-parent rectangle is represented by `null`; it does not imply viewport clipping. This distinction preserves source behavior when a caller selects the document root boundary. Disjoint clipping intersections retain signed edge distances for overflow calculations.

Native styles use React Native absolute positioning, numeric insets and translation transforms. The source `strategy` value remains available to native measurement adapters; browser CSS positioning and DOM selector semantics require native integration decisions. Native arrow options accept a View instance. A DOM selector is rejected. `applyStyles` is a platform publication callback; it does not mutate browser styles.

## Evidence and remaining integration

The source artifact is the latest stable MIT `@popperjs/core` 2.11.8 observed in the official npm registry on 2026-11-03. Its exact integrity, license and source-file hashes are retained in `upstream/native-positioning.json`. The implementation adapts that source rather than depending on the browser runtime. `scripts/reference/popper.mjs` verifies the pinned archive against the installed original reference before building the browser probe. An existing source record cannot be silently replaced by that script.

`tests/fixtures/mui-popper-geometry-9.5.0.json` records 88 actual original Chromium cases at 390 by 844. Native model comparisons check placement, modifier order/data, attributes, arrows and resolved positioning styles. They cover all placements, boundary and tether options, offset/rounding callbacks, oversized content, explicit and disjoint boundaries, reference clipping, document bounds and fixed strategy. Separate tests cover update batching, effect cleanup, cancellation, disconnected nodes, reset limits and invalid geometry. These are algorithm and model checks, not physical native interaction or performance measurements.

The native observation transport is separate from the public component and connected through its measured-frame adapter. It reuses Portal's native Android pre-draw and UIKit display-link tracking, publishes only changed geometry, and stops tracking inactive/detached hosts. A private, single-owner subscription rejects stale anchor/container revisions and invalidates old measurements on retargeting, closure and cleanup. It adds no JavaScript frame polling and does not send anchor movement through the public Portal container-layout callback.

Observation snapshots use window-space device-independent coordinates. They separate full window bounds, the usable viewport, anchor geometry and the physical clipping parents of reference and popup. Missing clipping parents and signed disjoint intersections remain distinct. Android includes native scroll/clipping, RN's source-pinned border-to-padding clip and system/IME insets. UIKit includes clipping surfaces and RN shape masks, safe areas and full-width docked keyboard-guide geometry. Unknown masks and perspective/singular transforms are not certified rectangular geometry. Virtual anchors without a context View subscribe to viewport/container changes using tag zero; the adapter maps their window-space rectangle into the current containing frame. These are implemented contracts with model/code-generation and native compile checks, not verified physical clipping or keyboard behavior.

The iOS viewport reads the keyboard guide from a connected controller root and converts its frame into the observed window's coordinates. It follows an attached presented root when a full-screen modal detaches the underlying view. This avoids treating an empty UIWindow guide as proof that no keyboard occupies the screen. Guide settings remain application-owned. Apple's [layoutFrame documentation](https://developer.apple.com/documentation/uikit/uilayoutguide/layoutframe) describes the owning-view coordinate system.

The measured adapter and public component now connect native snapshots, root slots/defaults/refs, open/keepMounted/transition lifecycle, automatic updates and installed-consumer original Popper imports. Native host 0.0.5-dev.0 requires rebuilding existing development applications; Expo Go cannot load it. Invalid or missing current anchor/context/boundary geometry gates visibility even when automatic updates are disabled. Modifier cycles retain one immutable frame, including replacement state objects, and reject retired reads before publication. Physical iOS/Android clipping, transforms, touch, keyboard, accessibility and calibrated release-performance gates remain open.

Geometry events coalesce on each platform so pending movement snapshots can be replaced by newer geometry. This is a queue safeguard, not a measured performance result. Container/eligibility invalidation renews the native observation revision, preventing pre-close snapshots from being accepted after reopening. Empty local clipping regions remain empty under rotation; affine bounds otherwise use axis-aligned rectangles, not exact rounded or rotated polygon intersections.
