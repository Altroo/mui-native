# Native FormGroup

FormGroup is the existing one-root grouping wrapper from pinned MIT Material UI 9.5.0. A native View replaces its browser div. It provides wrapping column/row layout; checked state, selection, activation and radio keyboard navigation belong to the child controls and RadioGroup.

```tsx
import { FormControl, FormGroup, Typography } from '@mui/material';
import { formGroupClasses } from '@mui/material/FormGroup';

<FormControl error>
  <FormGroup row sx={{ [`&.${formGroupClasses.error}`]: { borderWidth: 1 } }}>
    <Typography variant="inherit">Grouped content</Typography>
  </FormGroup>
</FormControl>;
```

## Finite public contract

| Surface                    | Native behavior and disposition                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| children/row               | Children, fragments and keyed elements are retained. row defaults to false, selects row versus column, and keeps flexWrap wrap. Native minWidth 0 remains additive. Caller-owned native child layout replaces browser inline formatting.                                                                                                                                                                                                                                      |
| inherited error            | Error comes from FormControl when the own value is undefined. Without a provider it remains undefined, rather than becoming false. An own false overrides inherited true for this wrapper. FormGroup does not replace the parent FormControl context for its descendants.                                                                                                                                                                                                     |
| error/component extensions | Native FormGroupProps retains an explicit error prop and native component replacement. Original JavaScript also reads an own error value, but its published FormGroupProps does not declare that prop. Native component replacement accepts a native ref, ViewProps and optional composed className metadata; browser string roots/HTML refs are not accepted.                                                                                                                |
| classes/className          | Original root/row/error identifiers compose with supplied classes in source order, followed by the separate className join. Inactive classes do not activate state. Nested class-map getters retain the source truthiness-then-append reads. Supported self selectors use these identifiers. Stock Views receive no CSS-only props; custom roots receive composed metadata. External CSS stylesheets are not rendered.                                                        |
| defaults and styles        | MuiFormGroup defaults, root then row overrides, embedded/component variants, sx and native inline style use shared System resolution. State selector specificity is retained. Wrapping styled self selectors resolve with the final row/error classes. Caller border, gap, flex and margin/padding shorthands replace computed longhands; arrays inside native style retain native edge precedence. Inherited direction and CSS text metric provenance survive normalization. |
| callback arguments         | Resolved row/error live in ownerState. Consumed row is absent from top-level root props, while composed className and forwarded id/attributes remain available to theme callbacks. The retained original root-argument case covers that distinction.                                                                                                                                                                                                                          |
| native attributes/events   | FormGroupProps inherits the actual RN 0.88.1 ViewProps surface, with native StyleProp replacing CSSProperties. Native IDs, accessibility/ARIA aliases, platform view options, layout, pointer/touch/responder, focus/key and accessibility callbacks retain their native signatures and original event objects. No group onChange, press action, browser submit or error announcement is invented. Platform dispatch remains a native gate.                                   |
| refs and roots             | The public ViewInstance is the actual owned root, including native measurement APIs. Object/callback refs and React 19 cleanup are preserved. A replacement root must forward the native ref, computed style, children and native attributes, and consume class metadata when needed. Arbitrary child refs/state are not intercepted.                                                                                                                                         |
| text                       | One React-only native text scope publishes inherited color/font metrics on the existing root. Literal runs get native Text hosts; direct Text/View and Typography retain their supported native types and metrics. Unitless CSS lineHeight remains relative for smaller descendants; native style lineHeight remains an absolute native length. No JavaScript multiplication substitutes for OS accessibility scaling.                                                        |
| declarations               | FormGroupProps, FormGroupClasses and FormGroupClassKey remain available through canonical entries. Classes is augmentable, while augmentation does not invent runtime states. Emitted strict consumers check the complete native host key surface, canonical augmentation, native refs/events, the original JSX.Element call result, and explicit undefined for row/classes/sx/className/error/component.                                                                     |
| slots/polymorphism         | The pinned component has no slots/slotProps or TypeMap API. None is fabricated. The existing native component extension is the explicit root replacement contract.                                                                                                                                                                                                                                                                                                            |

DOM nodes, HTML-only attributes, document selection/clipboard/drag events and browser form submission are outside the native View contract. Full arbitrary CSS, browser inline formatting and opaque custom components returning bare Text without a shared text boundary remain shared native adaptation limits. Use Typography variant="inherit", authored native Text styles or a shared text scope inside such custom components. See [text boundaries](text-containers.md) and [layout system](layout-system.md).

## Imports and provenance

Canonical imports are `@mui/material` and `@mui/material/FormGroup`, routed on native to `@altroo/mui-native` and its FormGroup entry. Root/canonical component entries expose FormGroup, formGroupClasses, getFormGroupUtilityClass and public types. Web keeps the original package.

The existing native-only `FormGroup/formGroupClasses` alias remains available through the native package/resolver. Pinned browser 9.5.0 ships that internal file but does not publish it as a package-export subpath. Use canonical named imports for shared web/native code; no new import route is introduced here.

The retained original fixture has **13 actual original cases and 20 utility observations**, not 13 native/device tests. It records source/license integrity, row/error/default/class behavior, class getter timing, and root callback arguments. [upstream/form-group.json](../upstream/form-group.json) points to those exact references and the fixture digest; package MIT notices remain in force. The shared files also implement other controls, whose completion status is not changed by this FormGroup increment.

## Catalog and open native gates

FormGroupContractExample is a standalone scene; catalog navigation owns its scroll container and route. Five normal-sized controls change row, parent error, theme, local RTL and authored 16/20 text units. Four permanent groups compare inherited error, own false, a custom native root and a wrapped styled root. Keyed child counters must retain state through every change. Their inline margin/padding zero resets deliberately override themed per-edge values.

Root test IDs are form-group-contract-inherited, form-group-contract-own-false, form-group-contract-custom and form-group-contract-styled. Toggle IDs end in row/error/theme/rtl/text; child counter IDs use form-group-contract-child-KEY. The receipt ID is form-group-contract-receipt. Its visible text stays short; accessibilityLabel contains schemaVersion, row, parentError, rtl, themed, fontSize, the actual RN fontScale, ref attach/cleanup counts, and local/window rectangles per root. Stable onLayout callbacks and native measureInWindow supply receipts; stale callbacks cannot replace newer rectangles. Repeated equal receipts do not trigger an update loop.

The maintained [iOS root tests](../tests/native/ios/RootLayoutCatalogUITests.swift) passed on iPhone 18 Pro / iOS 27 with the integrated styled/default handling. They exercised live row/error/theme/RTL/text changes, native frame receipts, retained refs and child counters, and stock/custom/styled roots. A separate run at the actual largest OS text setting (`fontScale` 3.571) passed the interaction and geometry checks. This establishes those assertions, not full screen-reader usability or unrestricted text shaping. Changing only the scene's authored font size is not an OS text test.

Android's maintained [root scenario](../tests/native/android/LayoutRootScenario.java) passed all fourteen Group/Avatar states, including eight Group states, on the existing API 37 emulator at actual OS text scales 1.0 and 2.0. Both runs exercised live row/error/theme/RTL/authored-text changes with retained refs and child counters. Fabric may paint a concrete View while mounting its contents as native siblings; the probe verifies exact native text/IDs, physical relationships, contained bounds and actual glyph paint rather than assuming DOM containment. At enlarged text, wrapping is evaluated from native measured child widths; conversion residue between adjacent rows does not count as a physical pixel of overlap. The current runner requires `--font-profile normal|enlarged`, forwards it to native instrumentation and rejects a missing/mismatched profile or actual native scale. Historical unlabelled reports remain readable but cannot satisfy an explicitly requested profile. Group glyph sizes are compared with Android’s SP converter using the rendered view’s resources, independently of React Native’s cached metrics. See [native profile commands](native-catalog-testing.md#formgroup-and-listitemavatar).

The separate native callback probe compares a plain React Native View with stock, custom and styled FormGroup roots. On the API 37 emulator at actual OS text scale 1.0, it passed twenty focus, blur and custom accessibility-action callbacks. Capture/bubble pairs retain the same event object, actual native target/currentTarget tags and ref identity. The native collector moves real hardware focus and invokes the exposed Inspect control action through UiAutomation; resetting the callback log retains all four roots. The probe uses `role="group"`, which the pinned Android runtime accepts; its legacy `accessibilityRole` does not accept the group value.

The same run authenticated `enableKeyEvents=false` in the actual native runtime. It does not establish hardware-key callback dispatch. The runner supports the enabled configuration and validates its real key/modifier pairs, while disabled captures retain that gap. iOS callback dispatch, detailed accessibility traversal, physical screen-reader usability and wider device profiles remain open. ### Child keyboard propagation

FormGroup forwards owned child key events through the same native View root. Stock, styled and ref-forwarding custom roots receive capture, child and bubble callbacks with the original root event and actual child target. Enter activates on key down; Space activates on key up. Capture `preventDefault()` cancels activation while retaining child delivery; capture `stopPropagation()` prevents child and bubble callbacks for that dispatch. ButtonBase retains the pinned MUI distinction between ancestor capture cancellation and its own Enter callback, which can still dispatch a separate click after calling `preventDefault()` itself.

Owned hardware events carry `nativeEvent.muiKeySource="hardware"`. Standard framework copies from the same owned InteractiveView target are filtered without suppressing ordinary View/TextInput events. Target ownership is weak and revoked on ref cleanup. Custom roots must forward native event props, including the owned transport props; a root that deliberately filters unknown event props must supply its own equivalent forwarding policy. Native host metadata changed, so rebuild the development app when testing this source.

The maintained Android `form-group-keyboard` scenario compares a raw View baseline, direct host, stock FormGroup, custom host root and styled FormGroup across Enter/Space/A and observe/prevent/stop policies. The collector requires all forty-five cases, exact callback ordering, same root-event identity, a distinct ButtonBase facade with the same native payload, actual root/child tags, cancellation flags and unchanged refs. This is separate from root-self key delivery when React Native's framework dispatch is disabled. Managed TextInput/composite commands with framework dispatch enabled, unavailable iOS Enter injection, physical keyboards and assistive technology remain separate gates. See [keyboard commands](native-catalog-testing.md#formgroup-child-keyboard).

The [iOS keyboard test](../tests/native/ios/FormGroupKeyboardCatalogUITests.swift) verified **30 Space/A cases** on iPhone 18 Pro / iOS 27: all five roots and three policies, exact down/up order and codes, original payloads, capture cancellation, single activation, retained focus and all ten refs. Native touch requests focus; only the real focus callback acknowledges it. Reset requires empty callbacks and click counters before key injection, and keyboard activation does not issue a new focus command.

The independent UIKit control receives complete raw Space/A pairs and an actual A text edit, but neither Return nor keypad Enter reaches it as a raw press pair in this setup. The matrix retains `status="partial"`, `verifiedCases=30` and `unverifiedRawKeys=["Enter"]`, then explicitly skips its unavailable remainder. This establishes those 30 assertions, not full iOS keyboard coverage. Return and keypad Enter keep distinct native codes when available. The final fresh-edit prerequisite is checked separately from the unchanged matrix; [test setup and limitations](native-catalog-testing.md#formgroup-child-keyboard) explain the distinction.

### Child focus and blur

Owned Button descendants now deliver native focus and blur to stock, styled and ref-forwarding custom FormGroup roots. Capture, child and bubble callbacks share the original event and native payload; target remains the actual child and currentTarget identifies each callback owner. The stock wrapper remains the same native View. No focus manager or extra host is inserted.

The adapter marks owned native focus and excludes Android's ordinary framework copy for an owned target. Focus from ordinary View/TextInput descendants retains its standard route through stock, styled and plain View roots. A custom InteractiveView root retains its existing onNativeFocus/onNativeBlur policy for foreign native descendants. Native focus commands remain asynchronous; invoking a public ref alone does not count as an observed callback.

The maintained [iOS focus test](../tests/native/ios/FormGroupFocusCatalogUITests.swift) passed on iPhone 18 Pro / iOS 27 at actual font scale 1.0, with 26 callbacks across all five root variants. Android's `form-group-focus` scenario passed on API 37 at scale 1.0, with 30 callbacks: its raw View baseline exposes the four ordinary framework parent copies that the owned adapter filters. The four owned variants each retain exactly six capture/child/bubble focus/blur callbacks, with original event and payload identity. Both tests retain all ten host refs/tags and cumulative request state through release and clear. Android additionally authenticates the actual view's focused state. See [focus testing](native-catalog-testing.md#formgroup-child-focus-and-blur). These checks do not certify physical keyboard navigation or screen-reader usability.

An [optimized iOS simulator workload](performance-layout-roots.md) records a source-bound earlier snapshot: 100 roots across sixteen updates, retained refs and child state, native readiness, process CPU and peak memory. It covers update behavior in that exact build; mount, scrolling, input latency, current-tip performance and representative physical-device measurements remain open. Full-project checks and fresh installed archive consumers pass for the integrated source.

Physical VoiceOver/TalkBack usability, keyboard and relevant IME behavior remain external evidence. This guide makes no component-wide 100%, package parity or publication claim.
