# Spacing and responsive native styles

`createSpacing` and `createBreakpoints` are available from the native `@mui/system` root mapping. `createTheme` uses them for `theme.spacing` and `theme.breakpoints`. Original MUI handles web imports.

```tsx
import { createTheme } from '@mui/material/styles';
import { Box, Stack } from '@mui/material';

const theme = createTheme({ spacing: [0, 4, 8, 16, 24] });
const inset = theme.spacing(2, 3); // "8px 16px"

<Box sx={{ padding: inset, [theme.breakpoints.up('sm')]: { p: 4 } }} />;
<Stack spacing={{ xs: 2, sm: 4 }} />;
```

Spacing supports numeric scales, literal string scales, readonly arrays, functions, mixed string/number arguments, negative values, fractions for numeric/function scales and zero through four arguments. Passing an existing spacing helper preserves its identity. Array indices must be available integers; invalid indices produce diagnostics. Public helper strings match pinned MUI examples, while the native resolver prevents invalid spacing results from reaching layout.

Native `sx` translates two-, three- and four-value padding/margin strings into native sides. It evaluates `px`, `rem`, percentages where native spacing accepts them, margin `auto`, and simple `calc(number * px/rem/percentage)` results from string spacing scales. Ordinary numeric `sx` spacing uses the theme scale; numeric style overrides remain literal native units. Stack uses the same resolver, so custom scales, literal lengths and responsive spacing work consistently. User `sx` can override Stack's default spacing.

## Breakpoints

The public helpers expose sorted `keys`/`values`, `unit`, `up`, `down`, `between`, `only`, `not`, and `internal_mediaKeys`. Numeric boundaries, custom `step` and custom breakpoint names are supported. `BreakpointOverrides` augmentation through `@mui/material/styles` is checked in a fresh installed consumer, including rejection of explicitly disabled default keys.

### Pure helper options and imports

**Development after `0.0.7-prealpha.0`.** The deep route and helper boundary/type corrections described here apply to development source and are absent from that published preview.

The published `@mui/system/createBreakpoints` entry exposes the named `unstable_createBreakpoints` helper for internal Pigment CSS integration. Native routing retains that entry and its factory identity. The existing native `createBreakpoints()` convenience also accepts omitted options; the original helper expects an options object.

`unit` and `step` explicitly accept `undefined` and use their defaults, including with TypeScript `exactOptionalPropertyTypes`. `between(start, end)` treats a numeric end as a literal boundary, even when the values object contains an identically spelled numeric name. A string end matching that registered name uses its configured value. Sorted `values` are a snapshot; query functions retain the original supplied values object. Explicit method, `keys`, and `internal_mediaKeys` options preserve their source override order and reference identity.

Spacing callbacks receive string arguments as well as numbers. The reserved internal `mui` marker preserves already-transformed input identity. Invalid JavaScript configurations follow the original helper boundaries instead of being treated as array-like scales. Native spacing diagnostics continue to use `configureDiagnostics` in every build; the original logs these development diagnostics through its console channel. These pure helpers return CSS strings, and their output still passes through the native style resolver when used in layout.

The focused helper fixture records 72 spacing cases and eight breakpoint configurations directly from the integrity-checked 9.5.0 archive. Reproduce it offline with `node scripts/reference/helper-contract.mjs --check`. Strict emitted-declaration coverage, including disabled breakpoint augmentation and explicit undefined options, runs with `node scripts/reference/check-helper-consumer.mjs`. This helper coverage does not close the broader responsive-style or native layout family.

Native width rules generated by these helpers work inside `sx`, component overrides and `styled`. Matching named breakpoint rules follow MUI's seeded breakpoint ordering, rather than depending on the input object's breakpoint order. Explicit media blocks and property-responsive objects preserve the tested upstream merge behavior. Matching state/slot selectors retain their higher specificity across media blocks and `sx` arrays. Rules with equal specificity preserve source order. Null or undefined responsive property entries remove an earlier declaration in the same media branch while allowing a lower-breakpoint value to remain in effect. The merged `typography` token follows upstream behavior: a null token leaves earlier typography declarations intact. Replacing a transformed alias retains its declaration position, so a later `padding` alias does not erase an already positioned `paddingLeft` declaration.

The native evaluator supports min/max-width conjunctions and MUI's `not all and` ranges in `px`, `em` and `rem`. Width queries use the viewport width provided by `useWindowDimensions`; they are not container queries. A direct `resolveSx` call can supply `{ width }`. Media `em`/`rem` use a 16 dp initial-size reference, independently of `theme.typography.htmlFontSize`; ordinary style `rem` conversion uses that theme value.

Dialog accepts custom breakpoint names for `maxWidth`, converts supported breakpoint units to native dimensions and clamps to available viewport width. Dialog `rem` caps use `theme.typography.htmlFontSize`; `em` caps use the body font size. Minimum width never exceeds a smaller configured maximum, and `slotProps.paper.sx` can customize the Paper radius. Top-level Dialog `sx` targets the modal root; see [modal migration](modals.md). A missing default `sm` in a custom breakpoint set falls back to available width. The `xs` case preserves the Material 444 dp minimum before viewport clamping.

## Limits and evidence

- Arbitrary CSS calculations, variables, container queries, orientation, print and user-preference media features remain unsupported. Unsupported queries/expressions emit diagnostics rather than producing invalid native styles.
- Relative `em` style lengths require typography context and remain unfinished; support for media `em` does not imply support for every CSS style unit.
- Spacing reference cases cover valid inputs. Upstream oddities such as a one-key `not()` query are not evidence that all generated CSS is meaningful; the native parser rejects unsupported output.
- Public theme and sx numeric line heights are CSS ratios, including values above four; `px`/`rem` lengths are absolute. Explicit native style line heights retain native units. See [typography normalization](typography.md) for inherited metrics and reset boundaries.
- Full typography inheritance, every responsive utility export, slot styling, RTL/logical-property cascade, font scaling and real-device responsive/accessibility evidence remain open gates.
- Jest resize tests exercise React Native's Dimensions subscription and native component props in its test runtime. They do not substitute for simulator/device visual or release-performance measurements.

## Existing style contract closure

The shared theme now retains all 25 original elevation tokens, custom concrete shadow layers and opt-in focus-visible outline settings. ButtonBase/Group/Button sheets participate in one native specificity calculation; actual native inline styles retain final precedence. Nested style-override arrays, callbacks and embedded variants use the original owner-state merge order. Shape borderRadius accepts number or string tokens; numeric sx factors preserve concrete px/rem/percentage arithmetic. The retained [original observations](../tests/fixtures/mui-system-style-closure-9.5.0.json) and [source reuse record](../upstream/reuse.json) identify the pinned inputs.

Before selecting component override slots, each evaluated native styled layer resolves every enumerable `styleOverrides` slot, including inherited slots. Callback arrays and embedded variants follow source getter, matching and throw order. An unused slot callback can therefore throw during rendering even when its returned CSS is not selected. Only selected CSS is prepared, so unused ordinary CSS values, diagnostics and nested variant-array callbacks stay deferred. The ten [original createStyled observations](../tests/fixtures/mui-style-overrides-9.5.0.json) cover this boundary; `node scripts/reference/style-overrides.mjs --check` reproduces them from verified MIT source. Retained native sheets do not rerun callbacks when descendants recollect their rules. Direct theme-field callback access and callback members of selected variant-style arrays remain native extensions. This does not establish general Emotion serialization, modular CSS layers or renderer-wide invocation-count parity.

Modern native boxShadow retains validated layers, spread/inset and currentColor using the final inherited/native foreground. Android before API 28 uses an explicit diagnosed numeric elevation fallback; inset shadows require API 29. Unsupported CSS expressions remain diagnostics. Theme source parity does not establish platform paint equivalence or release performance.

Native text roots register their resolved inherited values for physical Portal destinations. Scope comparison includes literal native text values, relative line-height provenance and semantic color objects. Equivalent render allocations do not broadcast new inheritance contexts; detached/cyclic destinations do not become text owners. This registry preserves native host geometry and caller ref cleanup.
