# Native ListItemAvatar

ListItemAvatar is the existing one-root wrapper from pinned MIT Material UI 9.5.0. It reserves space for caller-owned avatar content; it does not implement the separate Avatar component. Native Views replace the browser div. This page lists the full wrapper contract and keeps implementation checks separate from native evidence.

```tsx
import { ListItem, ListItemAvatar, Typography } from '@mui/material';
import { View } from 'react-native';
import { listItemAvatarClasses as classes } from '@mui/material/ListItemAvatar';

<ListItem alignItems="flex-start">
  <ListItemAvatar sx={{ [`&.${classes.alignItemsFlexStart}`]: { marginTop: '12px' } }}>
    <View
      accessibilityRole="image"
      accessible
      accessibilityLabel="Account owner"
      style={{ width: 40, height: 40 }}
    />
  </ListItemAvatar>
  <Typography>Account owner</Typography>
</ListItem>;
```

Exact optional undefined and class declaration merging have emitted-declaration consumer checks.                                                     |

The original HTML root attribute/event surface is adapted to the actual native View surface. DOM nodes, document selection/clipboard/drag events, HTML-only attributes, external CSS and arbitrary browser layout are not native APIs. Native event signatures are the pinned RN signatures, not React DOM SyntheticEvent casts. Existing System CSS/unit/media limits remain explicit in [layout system](layout-system.md) and [text boundaries](text-containers.md).

Opaque custom components that return bare RN Text cannot acquire CSS inheritance through a native View automatically. Use Typography variant="inherit", a shared native text scope, or authored Text styles inside such components. ListItemAvatar supplies the scope and preserves the component; it does not inspect or intercept arbitrary internals or refs. Moving into a Portal uses that Portal's physical destination text policy. This shared native boundary is not a promise of unrestricted DOM text parity.

## Reproduction

After the existing [isolated original-reference setup](theming.md), run:

```sh
node scripts/reference/list-item-avatar.mjs --check
node_modules/.bin/jest --runInBand tests/list-item-avatar.test.tsx tests/lists.test.tsx tests/material-text-roots.test.tsx
node scripts/reference/check-list-item-avatar-consumer.mjs
node --test packages/compat/list-item-avatar.test.cjs
```

The reference verifies source archive integrity, license hashes and executed original files before comparing eleven original wrapper/context/default/class observations and 17 utility identifiers. The focused tests cover the actual selector context, native root attributes, all declared native events, style priority, custom roots, relative metrics, keyed state, refs and Portal lifetime. The strict consumer reads emitted declarations and checks all native prop/event keys, class augmentation, exact optional undefined and original/direct root and canonical component-deep paths. Full-project validation and fresh installation of all nine local package archives pass, including the isolated strict wrapper consumer and canonical helper identities.

## Styling integration

Wrapping styled self selectors now resolve after the wrapper reads its actual parent alignment and composes root classes. Prepared outer callbacks retain their original arguments and execute once; context changes rebind selectors without remounting the root. The shared CSS cascade retains specificity and source order, followed by genuine native inline declarations. Border, gap, flex and inset shorthands replace earlier computed longhands while specific fields inside native arrays retain native precedence. Focused regressions cover these boundaries; native geometry and optimized workloads remain separate evidence.

## Native evidence and remaining gates

The catalog Wrappers tab opens ListItemAvatarContractExample alongside FormGroup. Its compact visible receipt retains complete native measurement metadata in accessibilityLabel. Its test IDs expose stock/custom/portaled roots, separate accessible child images, live alignment/theme/RTL controls and a stateful child. OS text size must actually change for enlarged-text validation; JavaScript font sizes remain authored units.

The maintained [iOS root tests](../tests/native/ios/RootLayoutCatalogUITests.swift) passed on iPhone 18 Pro / iOS 27 after shared styled/default integration. They verify the native 56-to-64-unit reservation change, custom roots, live alignment/theme/RTL updates, window Portal placement, native frame receipts and retained child/ref state. A separate run at the actual largest OS text setting (`fontScale` 3.571) passed its interaction and geometry assertions. Those results do not certify complete screen-reader traversal or every font profile.

The separate `testAvatarNativeAccessibilityExposure` method passed at actual font scale 1.0 on the iPhone 18 Pro simulator / iOS 27. It checks two distinct XCTest Image elements labeled Account owner, with their centers inside the measured inline and portaled wrapper frames. The custom action remains a separately identified enabled Button. Its native tap increments the counter, and its label continues to report count 1 after alignment, theme and RTL changes and after restoring the original settings. This verifies the selected native exposure and touch behavior at normal text size; it does not establish VoiceOver reading order or announcements.

The [Android root scenario](../tests/native/android/LayoutRootScenario.java) passed all fourteen Group/Avatar states, including six Avatar states, on API 37 at actual OS text scales 1.0 and 2.0. It checks native paint, root measurements, child counters, alignment/RTL/style updates and physical Portal placement. Wider event dispatch remains a separate local check. See the [normal and enlarged profiles](native-catalog-testing.md#formgroup-and-listitemavatar). An [optimized iOS simulator workload](performance-layout-roots.md) records update CPU, process peak memory and lifecycle checks for 100 roots in an earlier fingerprinted source snapshot. Mount, scrolling, input latency and current-tip optimized measurements remain open. Physical native geometry and actual glyph paint must be read from the installed app; unit tests and JavaScript font changes do not establish those results.

The separate [Android accessibility scenario](native-catalog-testing.md#listitemavatar-native-accessibility-tree) passed on API 37 at actual OS text scale 1.0. With the flag for including views marked unimportant cleared, it found different inline and portaled ImageView nodes labeled Account owner, each inside its measured wrapper, and one enabled Button with the expected native identifier and click action. A real tap changed the counter from 0 to 1. Its label and the native wrapper tags stayed consistent through the updated and restored stages. The test checked the advertised accessibility action and used a real touch for activation; it did not invoke the action through UiAutomation.

Physical VoiceOver/TalkBack traversal, representative physical-device geometry/performance and physical keyboard behavior for explicitly focusable roots or interactive children remain external evidence. This implementation and its local source/type tests alone do not mark the component, List family or package 100% complete.
