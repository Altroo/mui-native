## Reading the records

Each [package record](../compatibility/inventory) includes conditional import targets, root symbol provenance, direct type members, callbacks, slot members, type references and current native contracts, including root contracts re-exported from another native package. Both ESM and CommonJS declarations are parsed. MIT source dependencies such as @mui/utils are pinned and monitored separately, used to resolve re-exports, and do not create native import aliases or verified-support claims. Import counts cover targets with declarations, excluding package metadata; untyped runtime-only wildcard targets still need source review. Native-only exports are listed separately, and direct member matches are review candidates rather than type or behavior equivalence. Member summary counts use the .d.ts declaration files to avoid counting equivalent conditions twice. They include direct property, method, call, construct and index signatures, including overloads and nested literal members. Exact declaration text and syntax modifiers are retained; computed names and semantic type expansion still require review. Published `internals` paths remain visible for review; publication alone does not make them an agreed public compatibility contract.

Re-exports from unavailable external dependencies and ambiguous exports remain explicit gaps. Package root module format selects import/require branches; nested package.json overrides, custom conditions, namespace bodies and import-equals require semantic review. Inherited properties, generic instantiation, mapped types, conditional types and declaration merging need semantic review. A name match is recorded as `declared-unverified`, never as supported or verified. The inventory does not modify upstream detection, candidate or released-support state.

Preview packages are separate. @mui/x-chat@9.0.0-alpha.19 is blocked: Missing published license text; source reuse is blocked.

## Reproduce

`pnpm coverage:generate` uses existing pinned tarballs in `.cache/upstream`. On a new machine use `pnpm coverage:generate --fetch` to download missing immutable tarballs from npm, verify integrity and license/API snapshots, and generate the same records. Upstream code is never executed. `pnpm coverage:check` checks for drift without rewriting records. `pnpm coverage:verify` is the fast, offline CI freshness guard included in `pnpm check`: it verifies input and output hashes, the exact report set and unverified status without fetching tarballs or executing upstream code. It covers reviewed baselines, native source, package export maps, alias mappings, generators, immutable API snapshots and locked tools. Ordinary release-detection state changes do not invalidate it. Full regeneration remains the stronger provenance check. Update the declaration inventory when these inputs change.
